AURORA FOLLOW-UP — PROJECT REQUIREMENTS

1. PROJECT OVERVIEW
Aurora Follow-Up is a professional Streamlit-based client follow-up and payment communication assistant. It helps users create polished payment reminders, rewrite rough messages, respond to client replies, organize follow-up sequences, and track lightweight invoice/client records.

2. PLATFORM
- Python application
- Streamlit UI
- GitHub repository compatible
- Streamlit Cloud deployment compatible

3. AI ENGINE
- Use Google Gemini only.
- Model: Gemini 3.5 Flash-Lite.
- API secret name: GEMINI_API_KEY.
- The API key must never be hard-coded in source code.
- The API key must never be requested from application users.
- The application should read the private API key from the deployment environment / Streamlit Secrets.
- Users should be able to use the application without entering any API key.
- If the AI service is unavailable, professional built-in templates should provide a graceful fallback.

4. CORE PAYMENT FOLLOW-UP FEATURES
The application should support:
- First payment reminder
- Due-date reminder
- Overdue payment reminder
- Second follow-up
- Final reminder
- Payment confirmation request
- Partial-payment follow-up
- Promised-payment follow-up
- No-response follow-up
- General business follow-up

5. MESSAGE CUSTOMIZATION
Allow the user to provide:
- Client name
- Company name
- Invoice/reference number
- Amount
- Currency
- Due date
- Payment status
- Additional context

Allow selection of:
- Tone: Professional, Polite, Friendly, Firm, Very firm
- Length: Short, Standard, Detailed
- Channel: Email, WhatsApp, SMS

6. PROFESSIONAL COMMUNICATION RULES
Generated messages must:
- Be clear, polished, respectful, and business appropriate.
- Request payment or an update directly but diplomatically.
- Avoid threats, insults, accusations, or unnecessary aggression.
- Never invent dates, fees, legal consequences, payment terms, agreements, or other facts.
- Preserve user-provided facts.
- Avoid unnecessary emojis in professional communications.

7. EMAIL REWRITER
Provide a feature where users can paste a rough or poorly written message and receive a polished professional version while preserving the original facts and intent.

8. CLIENT REPLY ASSISTANT
Allow users to paste a client's response and generate an appropriate professional reply. The assistant should:
- Acknowledge the client's response.
- Respond only to information actually provided.
- Handle proposed payment dates appropriately.
- Avoid inventing agreements or concessions.
- Maintain the selected professional tone.

9. FOLLOW-UP SEQUENCE
Provide a structured sequence such as:
- Day 0 / initial reminder
- Due date
- +3 days / overdue
- +7 days / second follow-up
- +14 days / final reminder

The sequence should remain professional and should not automatically make unsupported legal or collection claims.

10. CLIENT / INVOICE TRACKING
Support lightweight records containing:
- Client
- Company
- Invoice/reference
- Amount
- Currency
- Invoice date
- Due date
- Status
- Last follow-up
- Next follow-up
- Notes

11. DASHBOARD
Provide dashboard information including:
- Total records
- Outstanding amount
- Overdue count
- Paid count
- Current client/invoice records

12. CLIENT HISTORY
Provide:
- Search across client/company/invoice information
- Current-session history view
- CSV export
- CSV import

13. DATA STORAGE
The initial version should not require a database.
Records can remain in the current Streamlit session.
Users should be able to export records as CSV.
The application must clearly communicate that session data is not a permanent database.

14. USER INTERFACE
Create a modern, premium business interface with:
- Deep blue / navy sky background
- Gold accents
- Blue and gold visual blending
- Subtle stars / sky-inspired visual elements
- Professional typography
- Rounded panels/cards
- Clean dashboard layout
- Strong readability
- Responsive Streamlit layout

The visual design should feel trustworthy, premium, modern, and suitable for professional business communication.

15. SETTINGS
Settings should allow non-sensitive application preferences such as:
- Business name
- Default currency
- Default signature

The Settings page must NOT provide an API-key input field.
The Settings page must NOT ask the user to configure Gemini.
It may explain that the AI credential is privately managed by the deployment.

16. SECURITY
- Never expose the Gemini API key in the UI.
- Never commit the Gemini API key to GitHub.
- Use Streamlit Secrets for deployment configuration.
- Do not place credentials in README files, requirements files, or source code.
- Do not collect unnecessary sensitive client information.

17. DEPLOYMENT
The project should be suitable for:
- GitHub repository upload
- Streamlit Cloud deployment
- requirements.txt dependency installation
- Streamlit Secrets configuration using GEMINI_API_KEY

18. GRACEFUL FAILURE
If Gemini is unavailable because the SDK, API key, quota, or service is unavailable:
- Do not crash the entire application.
- Use professional built-in templates where practical.
- Give the user a useful, concise status message.

19. QUALITY REQUIREMENTS
Before deployment:
- Validate Python syntax.
- Compile the Python file.
- Check imports and dependencies.
- Check that no API key is hard-coded.
- Check that no user-facing API-key input exists.
- Check that the intended Gemini model is used.
- Check CSV import/export logic.
- Check Streamlit UI sections.
- Check graceful fallback behavior.

20. EXPECTED PROJECT FILES
Recommended repository structure:
- app.py
- requirements.txt
- README.md
- .gitignore

The final application should be professional, maintainable, deployment-ready, and easy for a non-technical end user to operate.
